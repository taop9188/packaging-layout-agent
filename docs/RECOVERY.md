# 恢复、回滚与停止

## 1. Provider 504/up_timeout

1. 停止重试，保存错误时间、错误码、请求地址、模型 ID 和响应耗时的脱敏记录。
2. 备份 Provider 配置容器；不读取或复制 API Key 明文。
3. 分开验证 Base URL、协议、模型 ID、Key 存在性、超时/重试可见性和上游响应。
4. 只做一次最小请求定位；确认修复后再做 3 次连续请求和 1 次正常代码任务。
5. 若仍失败，恢复备份或保持原配置，标记 BLOCKED，不改用另一个模型掩盖问题。

## 2. Git 回滚

每次阶段变更必须保留提交 SHA。回滚优先创建反向提交或恢复到已核验的提交；不使用强制推送、破坏性 reset 或删除远端历史。`main` 的回滚也必须留下原因、操作者和新提交。

## 3. Worker/Adobe 中断

后续任务必须有任务 ID、输入哈希、锁和 checkpoint。应用崩溃、进程中断、输出损坏或状态不明时，隔离临时文件，保留原件，人工确认后从最近 checkpoint 恢复。

## 4. Secret 泄露

发现 Key 出现在日志、diff、URL、截图或文件中时，立即停止推送和后续任务；隔离证据，通知用户轮换凭据，清理历史必须遵循 GitHub 凭据泄露处置流程。未经轮换和独立确认，不得恢复 Provider 验收。

## 5. 文件损坏或非预期写入

比较写入前后的哈希和文件列表；只保留可解释的派生文件。不能确认范围时保留现场并 BLOCKED，不覆盖原文件，不通过聊天解释替代恢复证据。
