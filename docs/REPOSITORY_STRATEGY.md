# 零费用仓库策略

状态：P0 执行中，尚未完成 P1 迁移。

## 目的

在不购买 GitHub Pro 的前提下，保留 P0 的可复核分支门禁，同时避免包装业务源码进入公开仓库。

## 分阶段安排

| 阶段 | 仓库 | 可放入内容 | 不可放入内容 |
|---|---|---|---|
| P0 | GitHub Free 公开仓库 `taop9188/packaging-layout-agent` | 十份规范、测试骨架、门禁脚本、脱敏证据 | 包装业务代码、客户资料、真实 Adobe 文件、私密算法、凭据 |
| P1 起 | GitLab Free 私有项目 | 完整实现、测试、阶段证据和必要生产资产 | 明文凭据、无授权的客户数据和不可追溯产物 |

## P0 规则

- `dev` 用于开发和审查；`main` 只接受通过门禁的变更。
- GitHub 公开仓库的 `main` 必须启用免费可用的保护规则，要求通过 P0 工作流后才能合并。
- 公开仓库视为可能被复制；P0 通过后优先归档，不以删除作为保密措施。
- 任何发现业务代码、客户资料、真实 Adobe 文件或 Secret 被加入公开仓库，立即停止、撤回公开变更并按恢复规范处理。

## P1 迁移门

在 P1 前创建 GitLab Free 私有项目，核对文件清单、提交记录、分支和保护规则。完成迁移证据并得到用户/终审确认后，GitLab 才成为唯一源码基线。
